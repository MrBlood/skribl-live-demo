{# Stamps the stored theme on BEFORE first paint. This has to be inline, in , and NOT deferred. The setting lives in localStorage; no stylesheet can read it, so if the attribute is applied by a deferred script the browser has already painted the dark frame and a light-mode user sees it flash on every single navigation. It is a partial rather than two copies because the KEY is a contract shared with lib/theme.js, and a second copy of a contract is a second thing to drift — which is the whole subject of verify_surfaces.py. Kept deliberately tiny and total: any read failure (Safari private mode throws on ACCESS, not just on write) and any unrecognised value leave the attribute off, which is dark, which is the app as it has always looked. ?theme=light|dark ON THE URL WINS, for this document only (v288). A host that iframes /s/ cannot reach into the frame's localStorage and the frame cannot see the host's data-theme, so the host passes the theme it already stamps on its own page as a query parameter. Exact values only; anything else falls through to the stored preference. This is the one place a Skribl page follows something other than its own setting — and it is one of two places a Skribl page follows something other than its own setting; the other is the OS, since v292: with nothing stored (or "system" stored) the page follows prefers-color-scheme, and an explicit dark or light ignores it. Resolved HERE, before first paint, for the same reason the stored value is — a deferred script would flash. lib/theme.js is the same resolution for everything that runs afterwards; keep them agreeing. #}
