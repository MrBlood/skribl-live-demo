Highest value

Your Skribls

Post, get a link, close the tab, it's gone. There are no accounts, so the link is the only handle a tester has — and nothing tells them to keep it. The client already knows every id it has posted; this just remembers them.

Your Skribls
Saved in this browser only · clearing site data removes them

Stored as a small array in localStorage — id, title, kind, page count, timestamp. No payload, so it stays a few kilobytes however many you make. The honest footer matters: a tester who assumes this is an account will lose work and blame the app.

Before testers arrive

The rate limit needs a voice

Posting is capped at 20 an hour per person by default. An enthusiastic tester will hit that, and right now the failure is a bare error. It should say what happened, when it lifts, and that the work is safe.

You've posted 20 Skribls this hour

That's the limit for now. You can post again in 18 minutes. Your animation is still here and still saved — nothing was lost.

Set SKRIBL_RATE_MAX_POSTS deliberately before inviting anyone; the default of 20/hour is low for someone genuinely enjoying it. The countdown is real data — the limiter already knows the window.

You have no error reporting

Somewhere to say it's broken

During a test you find out about problems by being told. A one-tap report that captures what version and browser someone was on turns "it didn't work" into something you can act on.

Something not working?

Tell me what happened — I'll get your browser and version with it.

Sits in the … menu under "How it works". The captured context is the part that matters: SKRIBL_VERSION, user agent, canvas size, page count, and whether a draft restored — the things you asked me for by hand all session.
