# Skribl v328 — Independent Audit / Developer Handoff

**Classification:** substantial independent examination, **not** comprehensive browser/device release certification. **Release decision:** NOT READY for *unconditional launch sign-off* based on currently available evidence. This does not imply untested features fail.

Open **`AUDIT-v328-A-to-Z.md`** for the 26 deliverable sections and the tested/untested ledger. Open **`DEVELOPER-HANDOFF.md`** for the prioritized confirmed issue and remediation guidance. The archive includes independently designed probe scripts under `scripts/`, structured results and logs under `evidence/`, and externally supplied media artifacts under `media/` for reproducibility.

The **first confirmed product issue** is `AUD-002`, SQLite's `PUT /api/drafts/<id>` race. Read both the test code and its timed-overlap caveat before drawing conclusions about ordinary-user frequency. `AUD-001` is a release-harness issue, not a product bug, and the supplied post-v328 patch is included only for comparison; it is not applied to sealed v328. `HIST-001` is intermittent by developer report, not an independently observed app crash.

To rerun probes:

```bash
cd /path/to/skribl-v328-source
export SKRIBL_SOURCE="$PWD"
/path/to/Python3.12/bin/python /path/to/package/scripts/independent_http.py
/path/to/Python3.12/bin/python /path/to/package/scripts/draft_race.py
```

Python must have v328 app dependencies installed (using the supplied offline wheelhouse is supported). Each test creates and disposes of its own SQLite database. An output JSON file is written to the current working directory unless `SKRIBL_AUDIT_OUTPUT` is set. The race test uses a **runtime-only synchronization shim**: it waits at the first `_instant()` call after both requests have read the previous revision. It does **not** modify the application code on disk. The trace shows HTTP 500 and SQLite locking only in this constructed concurrency scenario.

The `.mp4` and `.webm` files in `media/` were **developer-generated**, not created by this audit; their frame counts and codec content were independently decoded with FFmpeg and summarized in `evidence/independent-media-analysis.json`. The static preview contact sheet was generated by **removing application scripts** and inlining HTML/CSS; it is useful only as a limited rendering smoke test, not evidence of actual browser UI behavior.

`BASELINE-HASHES.json` identifies the original sealed packages; none of those packages were edited. `SHA256SUMS` verifies this developer archive's constituent files. Archive verification and hash are recorded in the final chat delivery.
