## Installing

Two files, and both are needed. The root one is the application's runtime; the
harness one is test-only and must never be installed into production.

    pip install -r requirements.txt -r harness/requirements.txt
    python3 -m playwright install chromium

`harness/requirements.txt` explains the two traps it exists to close: Pillow's
absence makes `verify_sizeclass.py` report 81/82 while eight of its assertions
silently do not run, and Playwright's version is coupled to a Chromium build
number on disk. Read it before debugging an environment.

The interpreter must be the one `.python-version` pins. `verify_docs.py` fails
the whole run when it is not — deliberately, because evidence produced on a
different interpreter from the deployed one describes nothing.

In a fresh container, `harness/bootstrap.sh` does all of the above the way CI
does it — the pinned interpreter, the hash-locked lock, then this directory's
requirements — creates the tables on a fresh sqlite database, raises the
posting rate limit the way `run_harness.sh` does, and leaves a server on port
5001 for suites driven directly. It writes no run record.
`docs/SESSION-CONTEXT.md` covers the rest of the environment.

## Running

    ./harness/run_harness.sh verify_move.py verify_pages.py   # name them
    ./harness/run_harness.sh                                  # everything

To check a change before a pull request, run the suites it touches side by
side, each against its own fresh server (every suite reads `SKRIBL_BASE`):

    python3 harness/run_parallel.py -j 3 verify_parity.py verify_tools.py

A red from a suite release_run.py tags as measuring, or as sharing a store, is
re-run alone before it counts. It writes no run record; `run_harness.sh` remains the record.

A bare run works but takes well over an hour; `release_run.py` is the checkpointing
version for a full aggregate. Suites can also be driven directly, with a server
already up:

    python3 -c "from app import app, db; app.app_context().push(); db.create_all()"
    python3 -m flask --app app run --port 5001 --no-reload
    cd harness && python3 verify_audio.py

**Firefox** is CI's, after a merge: `harness/firefox_smoke.py` boots the five
pages, draws on both editors, posts from both, plays the link and counts the
frames in each editor's video, in Firefox. It is not a `verify_` suite, so a
bare run and a seal never meet it; there is no Firefox in the build container,
where it would only skip. `SKRIBL_SMOKE_ENGINE=chromium` runs the same steps on
Chromium, which is how a change to it is checked here.

## The rule for adding a check

**Calibrate it on a known-bad and a known-good case before believing it.**
See WORKING-AGREEMENTS.md for the four instruments this project shipped that could not
detect the defect they were written for — including one gate that would have
passed on the tree that motivated it, and an ink measure that returned a
constant and had been green since v206.

A green check is not evidence until it has been shown to go red.

**Wait for a state, not a number of seconds.** `harness/waits.py` has two:
`until(page, js, name, window=ms)` waits for the app's own signal (a saved
draft, music back after a reload) and then settles the rest of the old sleep;
`settle(page, ms)` stands in for a sleep after a load, a click or a reload, on
a browser passed through `waits.instrument()`. Settling comes back as soon as
nothing the page has in flight is due inside the old sleep, and never before:
a timer, a request, a database write, a decode, a chain of animation frames or
a scroll due inside it holds it (`verify_waits.py` drives each). `browsing.goto`, `pad_drawer` and
`pad_drawer_close` settle this way; on a browser without the counter they are
the old sleep. A sleep that guards an ABSENCE ("no toast within two seconds")
stays a sleep.

## Gotchas

- **The rate limiter will bite you.** `POST /api/skribls` allows 20/hour/IP, and
  the posting suites together sit just under it — so a few new posting assertions
  anywhere produce mystery 429s that look like validation failures. `run_harness.sh`
  exports `SKRIBL_RATE_MAX_POSTS=100000` to keep suites deterministic. The flip
  side is that the limiter is not under test in the harness; check it by hand, or
  run a suite with the variable set low.

- **`app.py` must be present at the app root.** It was missing from the v101 zip,
  which made every suite unrunnable. Check it survives the next zip.
- **Background processes may not survive between tool calls.** If you're driving
  this from an agent sandbox, start the server and run the suite in ONE shell
  invocation, or use `run_harness.sh`.

- `verify_compose.py` — COMPOSE MODE: the Pad opened from a host's composer
  (`/skribl-pad?compose=1`), driven end to end on the real `/feed` page through
  the real iframe. Its main instrument is a count of POSTs to `/api/skribls`,
  because the rule it exists to pin is that attaching a drawing PUBLISHES
  NOTHING — the API is create-only, so a design that published on "Add to post"
  would orphan a skribl and spend a posting slot on every edit, and would leave
  a published, unwithdrawable skribl behind whenever a draft was abandoned.
  Also pins that a re-opened editor gets the drawing back, that the draft
  preview is the real in-post player rather than a thumbnail, that the composed
  payload carries the post-time work (its own share card, so the feed poster is
  its drawing), and that the handshake never posts to a wildcard origin.

- `verify_inline.py` — the IN-POST player: a Skribl inside a host's feed
  (`skribl/static/inlineplayer.js`, the `/feed` preview). It is a second
  playback implementation, so this suite is built the way `verify_sharedrules.py`
  is: it posts one real drawing, plays it in the sealed player at `/s/<id>` AND
  in a feed post from the same clock, and asserts they are at the same point in
  the replay and have drawn the same thing. Also pins the product rules that are
  not visible in a screenshot — nothing is fetched until a tap, one Skribl plays
  at a time, sound is off by default and the choice is page-wide and session-only,
  scrolling out of view settles a post — plus a flip document whose pages carry

  `lib/holdtiming.js` rather than re-derived. Its pixel tolerances were set by
  MUTATION, and the first set was worthless: see the note beside them.

- `verify_input.py` — the coalesced pointer samples a per-frame listener
  throws away, which is why a fast circle drew as a polygon and a slow one did
  not. Pins the thinning rule (self-balancing: a slow stroke's dense samples
  are dropped, a fast stroke's sparse ones all survive) and that the eraser
  really does bypass the stabilizer, which a mis-bound `else` had it not doing.

- `verify_icons.py` — the tool tray's glyphs, measured as RENDERED rather than

  channel, because path coordinates say nothing about how much of the box a
  drawing occupies once stroke, caps and fills are added. Pins that no icon
  falls out of the set's size band (Fill shipped at 15.0x16.3 against a ~19x18

  draws something, and that nothing sits off-centre in its cell. It reports ink

  visual weight, and "improving" it made one icon visibly worse. Liquify is
  exempt from the height floor BY NAME, with the reason, because it is a smear
  and a smear is legitimately wide and low.

- `verify_stamps.py` — Stamps: the selection clipboard made persistent,

  position, that scaling one scales its stroke widths too, and — the assertions

- `verify_fill.py` — Fill. A region expressed as strokes, because the frame

  tolerance is anchored to the seed so a gradient cannot walk the canvas, and

- `verify_compactops.py` — stage 4: on the compact surface the page bar is

## Where a suite's rationale lives

**In the suite's own docstring, next to the assertions it explains.**

Eleven sections used to sit here, moved out of `START-HERE.md` at v282 on the
stated grounds that ten of the eleven were "the ONLY prose describing their
suite". That was measured at v284 and it was wrong: NINE of the eleven were
already documented in their own file — docstring, inline comment beside the
code, or the assertion's own failure message — and the sections restated them
in different words, which is why a verbatim diff scored them as barely
overlapping. Two carried something real (`verify_boot`'s calibration and
declaration-order rule, `verify_tools`' page-reuse guidance) and one,
`verify_tween`, carried six rules that existed nowhere else. Those went into the
suites; the rest were deleted.

The rule that came out of it: a suite explains itself. Prose about a suite,
kept anywhere but the suite, drifts from it and gets read by nobody editing it.
